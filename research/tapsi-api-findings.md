# Tapsi Food anonymous web API findings

Research snapshot: **2026-10-14**. This is an implementation brief for a **read-only, no-auth Python MCP**, not an API stability guarantee or an MCP implementation. Reference: [`snapp-mcp` main at `aef1470`](https://github.com/sepehr071/snapp-mcp/tree/aef14709260263df1add16dc2665ce28451c48a7) (21 tools: [location](https://github.com/sepehr071/snapp-mcp/blob/aef14709260263df1add16dc2665ce28451c48a7/src/snapp_mcp/location.py), [food](https://github.com/sepehr071/snapp-mcp/blob/aef14709260263df1add16dc2665ce28451c48a7/src/snapp_mcp/food.py), [market](https://github.com/sepehr071/snapp-mcp/blob/aef14709260263df1add16dc2665ce28451c48a7/src/snapp_mcp/market.py)). Its tools were also sampled live, one call each. Tapsi evidence is from anonymous site interactions, Chrome DevTools request/response inspection, then same-origin `fetch` with/without browser credentials and plain `curl` for already-discovered GET endpoints. The files in [`samples/`](samples/) contain captured JSON; some files (`vendor-list.json`, `reviews.json`, city verification files) are **evidence bundles/excerpts**, not verbatim endpoint bodies. Do not replay sample IDs/prices as fixtures: inventory, timing and discounts change.

## Executive findings and reading guide

- Tapsi's public site offers anonymous, location-aware search, store lists, full menus, vendor/product reviews and curated discounts. It also has grocery-adjacent business lines **inside the food catalog**, not the breadth of the separate SnappMarket catalog. Several Snapp tools can be composed client-side; coupons, exact cheapest-basket semantics and some market-specific capabilities lack observed equivalents.
- All tested GET endpoints at `https://api.tapsi.food` worked with **no authentication, cookies, or `x-*` headers** from a Tapsi page and via plain curl. Browser requests carry anonymous/session/edge headers, but these were not required in the tested requests. Geocoding alone does **not** establish delivery coverage.
- City selector actively offers **Tehran, Mashhad, Shiraz**. **Isfahan and Tabriz** are shown as «به زودی», and catalog endpoints return 404 or empty results there. Vendor detail may still return a full menu with `OutOfCoverage`; never treat HTTP 200 as deliverable.
- API prices and fees correspond to **Toman**: vendor dialog labels the 61,500 delivery price «هزینه پیک (تومان)» while the API returns `61500`; cards abbreviate 486,000 as `486` (thousands). Do **not** divide API amounts by ten. Some numeric strings/IDs and floating-point ratings require careful normalization.
- Each endpoint below is a **site-observed** path, not official documentation. `GET` is the only method needed for the proposed read-only surface. Examples deliberately omit volatile browser headers. Responses are trimmed but retain observed field names and types. Endpoint families share the `https://api.tapsi.food` base; `L=35.6892`, `G=51.389` in prose mean latitude/longitude respectively. Persian query/slug values must be URL encoded in curl.

## Endpoint contract and example requests

All examples below were first observed in the web browser. Base URL `https://api.tapsi.food`; anonymous `curl -G` with `--data-urlencode` handles Persian and avoids the observed **400 HTML** caused by raw unencoded Unicode in a shell URL. Unless specified, HTTP **200 JSON** on a served location, no body, no required headers/cookies/tokens. `curl` examples are read-only. Reuse a single client session and honor server throttling.

### 1. Location forward and reverse

```sh
curl -G 'https://api.tapsi.food/v1/api/Map/geocode/forward' --data-urlencode 'search_text=تهران' --data-urlencode 'district=51.389,35.6892'
curl -G 'https://api.tapsi.food/v1/api/Map/geocode/reverse' --data-urlencode 'subdivision=true' --data-urlencode 'local_address=true' --data-urlencode 'location=51.389,35.6892'
```

Forward `district` and reverse `location` are **longitude,latitude** strings, unlike search's separate `latitude,longitude`. Forward is search-biased, not city-restricted: «مشهد» with Tehran bias still finds Mashhad and Tehran streets named مشهد. Response examples: `{"results":[{"geo_location":{"south_west":{"lat":35.57,"lng":51.17},"north_east":{"lat":35.82,"lng":51.61},"center":{"lat":35.701737,"lng":51.385173},"title":"تهران","category":"District"},"description":"شهر تهران،تهران"}],"search_Type":"simple","consumer":0,"status":"OK"}` (bounds abbreviated here; exact [forward](samples/location-forward.json)); `{"address":"حر، خ. امام خمینی، بعد از خ. کارگر جنوبی، دانشگاه فرماندهی و ستاد آجا","subdivision_Prefix":"تهران","subdivisions":{"ostan":{"id":1001,"title":"تهران"},"shahrestan":{"id":100101,"title":"تهران"}},"certainty":92,"status":"OK"}` ([reverse](samples/location-reverse.json)). `category` observed `District|Street|Poi`; `results` length variable. No geocode pagination observed. Both minimal browser fetch and curl matched full browser responses byte-for-byte at Tehran. **Geocoder indexes unserved cities.**

### 2. Search suggestions, facets, products, vendors, aggregate

```sh
curl -G 'https://api.tapsi.food/v1/api/search-discovery/Search/suggestions' --data-urlencode 'query=پیتزا'
curl -G 'https://api.tapsi.food/v1/api/search-discovery/Search/facets' --data-urlencode 'latitude=35.6892' --data-urlencode 'longitude=51.389' --data-urlencode 'query=پیتزا'
curl -G 'https://api.tapsi.food/v1/api/search-discovery/Search/product-search' --data-urlencode 'latitude=35.6892' --data-urlencode 'longitude=51.389' --data-urlencode 'pageNumber=1' --data-urlencode 'pageSize=5' --data-urlencode 'query=پیتزا'
curl -G 'https://api.tapsi.food/v1/api/search-discovery/Search/vendor-search' --data-urlencode 'latitude=35.6892' --data-urlencode 'longitude=51.389' --data-urlencode 'pageNumber=1' --data-urlencode 'pageSize=5' --data-urlencode 'query=پیتزا'
curl -G 'https://api.tapsi.food/v1/api/search-discovery/Search/aggregated-search' --data-urlencode 'latitude=35.6892' --data-urlencode 'longitude=51.389' --data-urlencode 'query=پیتزا' --data-urlencode 'pageNumber=1' --data-urlencode 'pageSize=5'
```

Search UI `/search?query=پیتزا` requests facets and aggregate; `/search/product-list` and `/search/vendor-list` request the corresponding dedicated endpoint, page 2 when scrolling. `suggestions` returned `{"vendor":{"content":[],"categoryBased":[]},"product":{"content":[],"categoryBased":[]},"aggregated":{"content":[],"categoryBased":[]}}` in the observed query—**empty suggestions do not mean empty search**. Facets: `{"data":{"businessTypes":[{"name":"رستوران","id":"1","faName":"رستوران","count":982},...]},"message":"","statusCode":200}` ([Tehran](samples/verification-facets-tehran.json), [Mashhad](samples/verification-facets-mashhad.json)). `businessTypeIds[0]=13` filters خواربار, e.g. `--data-urlencode 'businessTypeIds[0]=13'` with `query=شیر`; the filter was observed on both aggregate and dedicated product search. [Filtered grocery product](samples/grocery-product-search-shir-bt13.json), [vendor](samples/grocery-vendor-search-shir-bt13.json), [aggregate](samples/grocery-aggregated-search-shir-bt13.json).

Example aggregate product, **actual captured values**, trimmed: `{"statusCode":200,"meta":{"totalVendors":12,"pageSize":5,"pageNumber":1,"totalItems":1130},"topVendors":[{"vendorCode":"5z68lm","vendorInfo":{"title":"پیتزا کیوان","rate":3.6,"ratesCount":30,"isOpen":true,"eta":55,"deliveryType":"OfoodDelivery","deliveryPrice":32000}}],"products":[{"id":"727124","productInfo":{"name":"غذای کودک پیتزا","price":465000,"priceAfterDiscount":465000,"discountRatio":0,"headerId":544341,"id":"727124","rate":null},"vendorInfo":{"title":"فست فود نی کُپیما ","vendorCode":"28k4gr","deliveryPrice":32000,"vendorStatus":true,"eta":55},"subDocs":[]}]}`. Real `subDocs` contains sibling matches; [full captured aggregate](samples/food-search.json). Dedicated product/vendor responses use `data[]`, `meta:{pageSize,pageNumber,totalItems}`, `filters`; aggregate uses `products[]`, `topVendors[]`, and its own `meta` including `totalVendors`. `queryId` changes between calls; do not use as stable product ID. Page numbering is **1-based**, while vendor reviews below are **0-based**. Facet IDs are strings. Isfahan/Tabriz return `200`, `data:[]`, `totalItems:0` rather than signaling coverage by HTTP status.

### 3. Paged discovery, business lines and curated collections

```sh
curl -G 'https://api.tapsi.food/v1/api/search-discovery/page-content/' --data-urlencode 'latitude=35.6892' --data-urlencode 'longitude=51.389' --data-urlencode 'bypassCache=false' --data-urlencode 'pageNumber=1' --data-urlencode 'pageSize=10'
curl -G 'https://api.tapsi.food/v1/api/search-discovery/page-content/business-line-15' --data-urlencode 'latitude=35.6892' --data-urlencode 'longitude=51.389' --data-urlencode 'bypassCache=false' --data-urlencode 'pageNumber=1' --data-urlencode 'pageSize=10'
curl -G 'https://api.tapsi.food/v1/api/search-discovery/page-content/تپ-تایم' --data-urlencode 'latitude=35.6892' --data-urlencode 'longitude=51.389' --data-urlencode 'bypassCache=false' --data-urlencode 'pageNumber=1' --data-urlencode 'pageSize=10'
```

Slugs seen: `business-line-15` restaurants; `business-line-7` groceries ([sample](samples/grocery-business-line-7.json)); `فودشات` discounted vendors; `تخفیف-فضایی` themed vendors; `تپ-تایم` flash products; other per-vertical slugs are CMS content, not hard-coded endpoints. Query may add `filtersAndSorts=1-82` (category), or filter keys exposed by `component.type=1025` such as `p-sort` (`ratingdesc|mostpopular|distance` in vendor lists), `p-deliveryType` (`OfoodDelivery|OwnDelivery`), `p-NewVendor`, `p-HasDiscount`; only chip filtering was exercised end-to-end in تپ‌تایم, so grocery chip request encoding and other filter combinations need confirmation. Observed first pages use `meta:{pageSize:10,pageNumber:1,totalItems:...}`, `config`, `content[]`; subsequent pages advance `pageNumber`. Homepage Tehran 23 *sections* (not 23 vendors), restaurant hub 192 sections/items, grocery hub 13, تپ‌تایم 166, فودشات 110. `content[]` intermixes `type:0` configuration/rail widgets and `type:1` vendor or `type:2` product rows; inspect `defaultFeedContent` only on feed rows, not every component. Example vendor row ([sample](samples/vendor-list.json)): `{"type":1,"defaultFeedContent":{"vendorCode":"569ywk","title":"پیتزا طهران","vendorStatus":"Open","discount":65,"deliveryType":"OfoodDelivery","deliveryPrice":64000,"minimumBasket":350000,"eta":55,"rate":4.2,"ratesCount":316,"categories":[{"id":158027,"name":"پیش غذا"}]}}`. Product row ([sample](samples/tapsi-product-collection-taptime.json)): `{"type":2,"defaultFeedContent":{"productId":"2121886","headerId":"1582926","productName":"رویال برگر با نان باگت","price":650000,"priceAfterDiscount":266500,"discountRatio":59,"discountStock":6,"vendorCode":"5w71ym","deliveryPrice":34000,"vendorStatus":"Open"}}`. `discountStock` exists only on some deals; countdown end time is a widget `options.countdownEndsAt`, not necessarily an absolute expiry. Never assume `meta.totalItems` is the count of products on mixed pages. Unserved city page-content gives **404** `{"status":404,"message":"Not Found","detail":""}`.

### 4. Vendor menu, costs, profile and reviews

```sh
curl -G 'https://api.tapsi.food/v2/api/Vendor/2y97wk/vendor' --data-urlencode 'latitude=35.6892' --data-urlencode 'longitude=51.389'
curl -G 'https://api.tapsi.food/v1/api/Vendor/2y97wk/profile' --data-urlencode 'pageSize=20' --data-urlencode 'pageNumber=0'
curl 'https://api.tapsi.food/v1/api/RateAndReview/1640969/review'
```

Vendor code is in URL; menu is location-sensitive (fee, coverage) and **not paginated**. Top-level menu `{"status":true,"message":"...","data":{"vendor":...,"review":...,"vendorCarousels":[],"categories":[]}}`. Trimmed actual example: `{"vendor":{"vendorCode":"2y97wk","title":"فست فود مارچوبه","vendorStatus":"Open","minimumBasket":400000,"packingPrice":0,"tax":false,"deliveryTypes":[{"deliveryType":"Ofood","deliveryPrice":61500}],"eta":55},"categories":[{"categoryId":"189516","categoryName":"پیتزا ایتالیایی","products":[{"productId":"1472033","productName":"پیتزا رست بیف ایتالیایی ( ۳۲ سانتی متری)","productVariations":[{"productVariationId":"1982313","price":1400000,"priceAfterDiscount":1400000,"discountRatio":0,"stock":100,"capacity":10,"discountStock":0,"optionCategories":[{"optionCategoryId":"68884","isMandatory":false,"options":[{"optionId":"198816","optionName":"کارد","price":3500}]}]}]}]}]}` ([menu evidence](samples/vendor-detail.json)). `productId` is the product/header ID; search's `id` may be a **variation** ID (`productVariationId`). Opening `/vendor/{code}/product/{productId}` or `?selectedProduct={productId}` reused menu data; no separate product detail GET observed. `stock:0` produces sold-out UI. `deliveryTypes:[{"deliveryType":"Unknown","deliveryPrice":-1}]` and `vendorStatus:"OutOfCoverage"` mean no service even though menu GET returns 200.

Profile `GET /v1/api/Vendor/{code}/profile?pageSize=20&pageNumber=0` includes `data.info` (address, minimumBasket, status), `data.shift` (today and weekly operating schedules), `data.insight.reviews[]` and `data.meta:{pageSize,pageNumber,total}`. Example `{"statusCode":200,"message":"Success","data":{"insight":{"reviews":[{"vendorCode":"2y97wk","writerName":"نگین حیدریان","createdAt":"2026-10-13T17:18:30.621Z","orderRating":5,"orderItems":[{"productName":"قارچ سوخاری","rating":5,"comment":"خیلی عالی و تازه بود فقط مشکل کم نمک بودنش بود","replies":[]}]}]},"meta":{"pageSize":20,"pageNumber":0,"total":88}}}` ([review evidence](samples/reviews.json)). The UI's displayed review count can differ from API `meta.total`. Product review `GET /v1/api/RateAndReview/{productId}/review` returned `{"statusCode":200,"message":"Success","data":{"reviews":[],"rateDetail":{"rate":0}}}` for milk [sample](samples/grocery-product-1867178-review.json); another rice product had `reviews:[{id,writer_name,rating,comment,created_at,updated_at,replies:[]}]`. Product-review pagination was **not observed**. No coupon endpoint was requested or observed in the read-only vendor flow.

**Cost inconsistency, same location and minute:** menu for `2y97wk` reported `minimumBasket:400000`, `vendorStatus:Open`; profile reported `minimumBasket:300000`, `vendorStatus:Close`; on-screen info dialog showed `۳۰۰٬۰۰۰` Toman and exact delivery `۶۱٬۵۰۰` Toman. Treat the two sources as conflicting, expose provenance or prefer the user-facing profile amount with a warning; do not silently imply a checkout-accurate minimum. Another grocery vendor `2nz941` returned `minimumBasket:300000`, delivery `38000`, and the UI matched the delivery price. No order quote was exercised.

## Anonymous transport, session and location implementation

Browser's `api.tapsi.food` GETs carried `x-platform: desktop`, `x-app-version: 0.4.192`, `x-usid` (anonymous ID), `x-usw: 1000`, `x-d-sx94k` (opaque), `Origin`, `Referer`, standard browser `Accept`/UA and cookies named `TS01e2279c`, `TS01f7c5be`, `BIGipServerOFD-Prod-Edge-VIP--443`, `_ga`, `_ga_43VHD0QXP9`. An `OPTIONS` 204 preflight appeared for some browser geocode requests. **Required set found by differential tests:** none beyond a valid URL: credentials-omitted page `fetch` using only `Accept: application/json` matched ordinary browser fetch for sampled endpoints, and plain curl matched status/semantic JSON for tested requests. No Bearer token, login, cookie bootstrap, signed-header generation or refresh procedure is needed **at present**. `x-usid`/`x-d-sx94k` should not be copied from a browser or assumed stable. A Python client should issue ordinary anonymous GETs, URL-encode Persian and brackets, set a modest timeout and identify itself honestly; if later 401/403 occurs, report API change rather than attempting login or forging browser tokens. Optional HTTP keep-alive is not an auth session.

Location is explicit on business GETs as `latitude`/`longitude` (numbers), on geocoding as **`lng,lat`**, and on clusters as bounds/zoom. Site confirmation at `/location` makes its own UI navigate home but is unnecessary to pass coordinates to the API. No location cookie/storage key was found before confirmation; cross-city coordinate-only requests changed the returned catalog with browser credentials omitted. Same vendor code at another coordinate may return `OutOfCoverage`; do not infer a city by `cityId` alone. A standalone server can accept coordinates supplied by the caller, obtain them from forward geocoding when requested, and reject out-of-coverage delivery results; there is **nothing to refresh for auth/location**. For a supported-city helper, use a documented snapshot of three active cities and make clear it is not a live city-list API.

Response throttling headers observed: `ofd-ratelimit-limit: 500`, `ofd-ratelimit-observed`, `ofd-ratelimit-remaining` (e.g. remaining ~419–476); reset period and per-IP/account scope **unknown**. Across location/listing/search/vendor samples no Cloudflare challenge, 401 or 429 was seen. This does not establish that production hosting outside the browser/IP region will always work; curl tests were from this workstation/harness. Use low concurrency, pagination bounds and backoff on 429 rather than sweeping all products/vendors.

## Risks and open questions

1. **Terms/compliance**: inspect Tapsi Food's current ToS, robots/crawling policy and permitted redistribution before deployment; none was verified here. Anonymous endpoint accessibility is not permission. No account/cart/order/payment route was used.
2. **Undocumented and mutable CMS/API**: slugs, widget type codes, filter values, status enums, response fields and version paths can change without notice. Unknown widget types and nullable fields appeared; preserve raw evidence and fail explicitly on unknown critical contracts. Product `id` vs `headerId` vs menu `productVariationId`/`productId` must be joined deliberately.
3. **Costs are not a final checkout quote**: same-point menu/profile minimum and status differed (`400000/Open` vs `300000/Close` for `2y97wk`), UI agreed with profile minimum. Why? Caching, independently maintained sources or time/status transitions unproven. Tax is a boolean; actual tax amount and coupons were not read. Check source recency and avoid promising orderability.
4. **Coverage beyond three active cities**: geocoder responds for Isfahan/Tabriz, vendor menu remains 200, but catalog is absent; which neighborhoods within active cities are served, and will city list update dynamically? No city API discovered.
5. **Rate limits and access policy**: `ofd-ratelimit-limit:500` observed, reset window/edge-IP scoping unknown; no 429/bot challenge observed from this network. Will a hosted IP outside Iran or higher volume face geo-blocking, WAF, signed headers, or CORS changes? Test deployment environment separately and back off.
6. **Parity gaps**: no coupon/rewards feed, full SnappMarket hierarchy/brand/chain SKU equivalence, grocery flash deals or precise single-person free-delivery rule observed. Grocery search sample `شیر` yielded one خواربار item among many non-grocery items; compare product names cautiously.
7. **Validation remaining**: confirm UI-selected `p-sort`, `p-HasDiscount` and combined filter encoding; whether search backend offers exhaustive sort/stock and nontrivial suggestions; whether product reviews paginate; whether collection countdown is timezone-specific or absolute; verify map-cluster curl/minimal headers and additional city coverage if those become committed MCP features. These are not prerequisites to the documented GET read paths.
